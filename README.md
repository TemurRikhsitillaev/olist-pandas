# Olist delivery SLA — воспроизведение на pandas

Операционный анализ сроков доставки бразильского маркетплейса Olist,
выполненный на pandas. Это повторение проекта
[olist-delivery-sla](https://github.com/TemurRikhsitillaev/olist-delivery-sla),
сделанного на PostgreSQL.

Цель — не новый результат, а **независимая проверка**: тот же анализ, другой
инструмент, и каждое число должно совпасть с тем, что дал SQL. Все контрольные
значения оформлены как `assert`, поэтому ноутбук либо проходит сверху вниз
целиком, либо останавливается на том шаге, где разошлось.

Сошлось всё.

## Что внутри

Ноутбук `olist.ipynb`, шесть шагов:

1. **Загрузка данных** — чтение CSV, разбор дат, проверка типов.
2. **Рабочая выборка** — четыре условия отбора, 99 441 → 96 203 заказа.
3. **Расчётные столбцы** — срок доставки, признак опоздания, отклонение
   от обещания, месяц покупки, обещанный срок.
4. **Распределение по корзинам** — семь интервалов, доли и накопленная доля.
5. **Динамика по месяцам** — доля опозданий, медиана, p90 и запас обещания
   по каждому из 20 месяцев.
6. **Оценки покупателей** — связь оценки с опозданием и со сроком доставки.

## Данные

Датасет [Brazilian E-Commerce Public Dataset by Olist](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)
с Kaggle. В репозиторий не входит.

Скачать, распаковать и положить в папку `data/` рядом с ноутбуком. Нужны три файла:

```
data/
├── olist_orders_dataset.csv
├── olist_customers_dataset.csv
└── olist_order_reviews_dataset.csv
```

## Замечание про формат дат

Файл `olist_orders_dataset.csv`, с которым выполнялся анализ, прошёл через
табличный редактор: даты в нём записаны как `10/2/17 10:56` вместо исходного
`2017-10-02 10:56:33`. Секунды потеряны, порядок «месяц/день» неочевиден.
Поэтому в `read_csv` задан шаблон `%m/%d/%y %H:%M`.

На результаты это не влияет: срок доставки, признак опоздания и отклонение
от обещания считаются по календарным датам, время в них не участвует.

Если скачать файл с Kaggle заново, формат будет ISO с секундами — тогда
шаблон нужно заменить на `%Y-%m-%d %H:%M:%S`. Файл отзывов в обоих случаях
в формате ISO.
